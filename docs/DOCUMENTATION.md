## Installation Guide

### Overview

This guide covers deploying AI Education Studio on a production Ubuntu server using Nginx, PHP-FPM 8.3, MySQL 8.0, Redis, and Supervisor. The application is built on Laravel 13 with a React frontend.

> **Warning:** This guide assumes you have root or sudo access to an Ubuntu 22.04 LTS or 24.04 LTS server. If you are using shared hosting, Docker, or a different OS, this guide may not apply.

### Prerequisites

Before starting, ensure you have:

- A VPS or dedicated server running Ubuntu 22.04/24.04 LTS
- A domain name pointed to your server's IP address
- SSH access to the server
- Basic familiarity with the Linux command line

### Step 1: Install System Dependencies

Connect to your server via SSH and update the package list:

```bash
apt update && apt upgrade -y
```

Install the required system packages:

```bash
apt install -y nginx mysql-server redis-server supervisor \
    php8.3-fpm php8.3-cli php8.3-mysql php8.3-redis php8.3-mbstring \
    php8.3-xml php8.3-bcmath php8.3-curl php8.3-zip php8.3-gd php8.3-intl \
    git unzip curl
```

> **Info:** These PHP extensions are required by Laravel and the application's dependencies (image processing, HTTP requests, XML parsing, etc.).

Install Composer:

```bash
curl -sS https://getcomposer.org/installer | php
mv composer.phar /usr/local/bin/composer
```

Install Node.js 22.x:

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | bash -
apt install -y nodejs
```

### Step 2: Configure MySQL

Run the MySQL secure installation script:

```bash
mysql_secure_installation
```

Create a database and user for the application:

```bash
mysql -u root -p
```

In the MySQL prompt, run:

```sql
CREATE DATABASE ai_education_studio CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'ai_edu_user'@'localhost' IDENTIFIED BY 'your_strong_password_here';
GRANT ALL PRIVILEGES ON ai_education_studio.* TO 'ai_edu_user'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

> **Warning:** Replace `your_strong_password_here` with a secure password. Save this password — you will need it in the `.env` file.

### Step 3: Configure the Application

Create the application directory:

```bash
mkdir -p /var/www/ai-education-studio
cd /var/www/ai-education-studio
```

Upload your application files to this directory. If you are cloning from a repository:

```bash
git clone https://github.com/your-repo/ai-education-studio.git .
```

Or upload the ZIP file and extract it:

```bash
unzip ai-education-studio.zip -d /var/www/ai-education-studio
```

Set the correct permissions:

```bash
chown -R www-data:www-data /var/www/ai-education-studio
chmod -R 755 /var/www/ai-education-studio
chmod -R 775 /var/www/ai-education-studio/storage
chmod -R 775 /var/www/ai-education-studio/bootstrap/cache
```

> **Warning:** The `storage` and `bootstrap/cache` directories must be writable by the web server (`www-data`). Without this, the app will crash with permission errors.

### Step 4: Install PHP and Node Dependencies

Install PHP dependencies:

```bash
cd /var/www/ai-education-studio
composer install --no-dev --optimize-autoloader
```

Install Node.js dependencies and build the frontend:

```bash
npm install
npm run build
```

> **Info:** `npm run build` compiles the React frontend for production. Do not use `npm run dev` in production — it starts a development server, not a production build.

### Step 5: Run the Install Wizard

The application includes a built-in install wizard that handles all configuration automatically. After uploading files and installing dependencies, visit your domain in a browser:

```
https://yourdomain.com/install
```

> **Info:** The install wizard replaces the manual steps of editing `.env`, running migrations, and creating the first user. If the wizard does not load, ensure `npm run build` completed successfully and the `.env` file exists (even if empty).

The wizard has 6 steps:

1. **System Requirements** — Checks PHP version (8.3+), required extensions, file permissions, and `.env` file presence. Fix any failing checks before proceeding.
2. **License Key** — Enter the license key generated by your CRM. The wizard validates it with the license server before continuing.
3. **Server Configuration** — Enter your application URL (e.g., `https://yourdomain.com`).
4. **Database Setup** — Enter your MySQL credentials (host, port, database name, username, password). The wizard tests the connection before proceeding.
5. **Admin Account** — Create the first Super Admin by providing an email and password (minimum 8 characters).
6. **Installation** — The wizard writes the `.env` file, runs migrations, seeds the database, creates the admin user, activates the license, and locks the wizard.

After completion, click **Go to Login** and sign in with your admin credentials.

> **Warning:** The install wizard can only be run once. After completion, the `/install` route is locked. To re-run, delete the `.install.lock` file from the project root.

### Step 6: Configure Queue Workers

AI grading and other background tasks run via Laravel queues. Configure Supervisor to keep the queue worker running:

Create a Supervisor config file:

```bash
nano /etc/supervisor/conf.d/ai-education-worker.conf
```

Add the following content:

```ini
[program:ai-education-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /var/www/ai-education-studio/artisan queue:work database --sleep=3 --tries=3 --max-time=3600
directory=/var/www/ai-education-studio
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=2
redirect_stderr=true
stdout_logfile=/var/www/ai-education-studio/storage/logs/worker.log
```

Tell Supervisor to read the new config:

```bash
supervisorctl reread
supervisorctl update
supervisorctl start ai-education-worker:*
```

> **Warning:** If queue workers are not running, students can submit exams but they will never be AI-graded. This is the most common cause of "my exam is stuck" issues.

### Step 7: Configure the Scheduler

Laravel's scheduler handles periodic tasks, including weekly license re-verification. Add this cron entry:

```bash
crontab -e
```

Add this line:

```cron
* * * * * cd /var/www/ai-education-studio && php artisan schedule:run >> /dev/null 2>&1
```

> **Info:** The scheduler runs every minute and checks if any scheduled tasks (like license verification, cache clearing, report generation) need to run.

### Step 8: Configure Nginx

Create an Nginx server block:

```bash
nano /etc/nginx/sites-available/ai-education-studio
```

Add the following configuration:

```nginx
server {
    listen 80;
    server_name yourdomain.com www.yourdomain.com;
    root /var/www/ai-education-studio/public;

    index index.php index.html;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/var/run/php/php8.3-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
    }

    location ~ /\.(?!well-known).* {
        deny all;
    }

    location ~* \.(jpg|jpeg|png|gif|ico|css|js|svg|woff|woff2|ttf|eot)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

Enable the site:

```bash
ln -s /etc/nginx/sites-available/ai-education-studio /etc/nginx/sites-enabled/
nginx -t
systemctl reload nginx
```

> **Info:** The `try_files` directive is critical. It ensures that Laravel handles all routing (including React Router paths) instead of Nginx returning 404s.

### Step 9: Set Up SSL with Let's Encrypt

Install Certbot:

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d yourdomain.com -d www.yourdomain.com
```

Follow the prompts. Certbot will automatically update your Nginx config with SSL and set up auto-renewal.

### Step 10: First Login

After completing the install wizard, visit `https://yourdomain.com/login` and sign in with the Super Admin email and password you created during installation.

> **Info:** After logging in, immediately configure the LLM provider and Stripe billing (see the [Super Admin Guide](#super-admin-guide)).

### Troubleshooting

#### "500 Server Error" on first load

- Check `storage/logs/laravel.log` for the specific error.
- Verify `.env` file exists and is readable.
- Ensure `storage/` and `bootstrap/cache/` are writable by `www-data`.

#### "SQLSTATE[HY000] [1045] Access denied"

- Double-check database credentials entered in the install wizard.
- Verify the MySQL user exists and has permissions: `SHOW GRANTS FOR 'ai_edu_user'@'localhost';`

#### "The public/storage directory does not exist"

- Run `php artisan storage:link`.
- If it says "link already exists", delete `public/storage` first, then re-run.

#### "Queue worker not processing jobs"

- Check Supervisor status: `supervisorctl status`
- Check worker logs: `tail -f /var/www/ai-education-studio/storage/logs/worker.log`
- Ensure `QUEUE_CONNECTION` in `.env` is set to `database` or `redis`.

#### "npm run build fails"

- Ensure Node.js 22.x is installed: `node -v`
- Delete `node_modules` and reinstall: `rm -rf node_modules && npm install && npm run build`

#### "Install wizard shows 500 error"

- Check `storage/logs/laravel.log` for the exact error.
- Ensure `.env` file is writable by the web server (`www-data`).
- Verify the license server endpoints are configured in `.env` (`LICENSE_ACTIVATE_URL`, `LICENSE_CHECK_URL`).

#### "License shows Pending after installation"

- Go to **Super Admin → License** and click **Re-verify Now**.
- Check that the license server is reachable from your server.
- Verify the CRM-generated license key is correct.

#### "License shows Invalid"

- Go to **Super Admin → License** and enter a new valid license key.
- Ensure the license has not expired in your CRM.
- Check that the domain matches the one the license was activated for.

## Super Admin Guide

### Overview

The Super Admin is the highest-level administrator. The install wizard automatically creates the first Super Admin account. After logging in, the Super Admin controls global settings: LLM configuration, billing, credit packages, institutes, website branding, and license management.

### First Login

After completing the install wizard, open your browser and navigate to `https://yourdomain.com/login`.

1. Enter the email and password you created during the Admin Account step of the install wizard.
2. You will be redirected to the **Super Admin Dashboard**.

> **Info:** The Super Admin dashboard shows an overview of all institutes, total credit usage, recent transactions, and quick links to key settings.

### LLM Configuration

Before any exam can be AI-graded, you must configure an LLM provider. This is a one-time setup step.

1. In the sidebar, click **LLM Configuration**.
2. You will see a form with the following fields:
   - **Provider** — Choose from:
     - OpenAI
     - Anthropic
     - Google Gemini
     - OpenAI-compatible (DeepSeek, Qwen, Together, OpenRouter, Groq, Ollama, and others)
   - **Model** — Enter the exact model identifier:
     - OpenAI: `gpt-4o`, `gpt-4-turbo`, `gpt-3.5-turbo`
     - Anthropic: `claude-3-5-sonnet-20241022`, `claude-3-opus-20240229`
     - Google: `gemini-1.5-pro`, `gemini-1.5-flash`
     - OpenAI-compatible: Check your provider's documentation (e.g., `deepseek-chat`, `qwen-max`)
   - **API Key** — Paste your API key from the provider's developer console.
   - **Base URL** — **Only required for OpenAI-compatible providers.** Leave blank for OpenAI, Anthropic, and Google. For custom providers, enter the API endpoint (e.g., `https://api.deepseek.com`).
3. Click **Save**.
4. Click **Test Connection** to verify the API key and model work.

> **Warning:** Only one LLM configuration can be active at a time. Saving a new configuration automatically deactivates the previous one. Changes are audited — each field change is logged with the Super Admin who made it.

> **Tip:** If you are using an OpenAI-compatible provider and get a connection error, double-check that the Base URL does not end with a trailing slash and includes the correct protocol (`https://`).

### Stripe Billing Setup

To allow institutes to buy credits, connect your Stripe account.

1. Go to **Super Admin → Billing**.
2. Enter your **Stripe Secret Key** (starts with `sk_live_` for production, `sk_test_` for testing).
3. Enter your **Stripe Webhook Secret** (from your Stripe Dashboard → Developers → Webhooks).
4. Click **Save**.

> **Warning:** The webhook endpoint in your Stripe Dashboard must point to `https://yourdomain.com/stripe/webhook`. The app validates webhook signatures to prevent spoofing.

#### Setting Up the Stripe Webhook

1. Log in to your Stripe Dashboard.
2. Go to **Developers → Webhooks**.
3. Click **Add an endpoint**.
4. Enter the endpoint URL: `https://yourdomain.com/stripe/webhook`
5. Select the event: `checkout.session.completed`
6. Copy the **Signing secret** and paste it into the app's Billing settings.

> **Info:** When an institute buys credits, Stripe sends a webhook to this endpoint. The app validates the signature, checks for duplicate processing, and atomically adds credits to the institute's balance.

### Credit Package Management

Credit packages are bundles that institutes can purchase. You define the credit amounts and pricing.

1. Go to **Super Admin → Credit Packages**.
2. Click **Create Package**.
3. Fill in:
   - **Package Name** — e.g., "Starter Pack"
   - **Credits** — e.g., `100`
   - **Price** — Amount in cents (e.g., `1000` for $10.00)
   - **Currency** — e.g., `usd`
4. Click **Save**.

Institutes will see these packages in their Billing section and can purchase them via Stripe checkout.

> **Tip:** Create multiple tiers (e.g., Starter 100 credits, Pro 500 credits, Enterprise 2000 credits) to give buyers options.

### Institute Management

Institutes are your tenants. Each institute has its own users, exams, and credit balance.

1. Go to **Super Admin → Institutes**.
2. The list shows all institutes with their status, credit balance, and user count.
3. **Toggle Status** — Disable an institute to block all its users from logging in.
4. **Adjust Credits** — Manually add or remove credits from an institute's balance (useful for refunds or promotions).
5. **Delete** — Permanently remove an institute and all its data. **This action cannot be undone.**

> **Warning:** Deleting an institute removes all associated users, exams, attempts, and results. Use with extreme caution.

### Website Settings

Control the public-facing branding and behavior of the application.

1. Go to **Super Admin → Settings → Website**.

#### Branding Tab

- **Site Name** — Appears in the browser tab title, navbar, and footer.
- **Tagline** — Shown on the public welcome page under the site name.
- **Site Logo** — Upload a logo (PNG, JPG, SVG, ICO, WebP; max 2MB). Resized to 400px wide automatically.
- **Favicon** — Upload a favicon (PNG, JPG, ICO, WebP; max 1MB). Resized to 64x64 automatically.

#### Contact & Social Tab

- **Support Email** — Shown in the welcome page footer with a mailto link.
- **Social Links** — Facebook, Twitter/X, LinkedIn, and Instagram URLs. Shown in the welcome page footer.
- **Footer Text** — Custom text shown in the footer (e.g., copyright notice).

#### Feature Flags Tab

- **Registration Open** — Toggle whether new users can register. When disabled, the `/register` page shows a "Registration is closed" message.
- **Maintenance Mode** — Toggle whether the platform is in maintenance. When enabled, all non-Super-Admin users are redirected to a maintenance page. Super Admins can still access all pages.

> **Info:** Changes to website settings are cached for performance. If you don't see changes immediately, clear the application cache: `php artisan cache:clear`.

### License Activation

The platform requires a valid license to operate. The license is generated by your CRM after you log in via Envato.

1. Go to **Super Admin → License**.
2. You will see the current license status:
   - **Active** — License is valid and verified.
   - **Pending** — License verification failed (e.g., network issue). A 24-hour grace period is active.
   - **Invalid** — License was rejected by the CRM. Platform access is restricted.
3. To activate or re-activate:
   - Click **Change License Key**.
   - Enter the license key provided by your CRM.
   - Click **Activate**.
4. The system will call the CRM license server, bind the license to your domain, and update the status.
5. Click **Re-verify Now** at any time to manually check the license status with the CRM server.

> **Info:** The license status is automatically re-verified weekly via a scheduled command. If the CRM server is unreachable, the status stays unchanged for 24 hours, then becomes **Pending** for up to 7 days, and finally **Invalid** if the server remains unreachable.

> **Warning:** If the license becomes Invalid, all non-exempt routes will redirect to the license page until a valid license is activated. The public welcome page and login/logout routes remain accessible.

## Institute Admin Guide

### Overview

Institute Admins manage their own institute: creating exams, enrolling students, viewing results, and purchasing credits. Each institute is fully isolated — Admins cannot see other institutes' data.

### Dashboard

After logging in, the Institute Admin sees:

- **Exam Count** — Total exams created (draft and published)
- **Student Count** — Total enrolled students
- **Credit Balance** — Remaining credits available for AI grading
- **Recent Attempts** — Latest exam submissions from students
- **Quick Actions** — Create Exam, Invite Student, Buy Credits

### Creating an Exam

1. Go to **Admin → Exams**.
2. Click **Create Exam**.
3. Fill in the exam details:
   - **Title** — e.g., "Midterm Mathematics"
   - **Description** — Optional context shown to students before starting
   - **Class Name** — e.g., "Grade 10"
   - **Subject Name** — e.g., "Mathematics"
   - **Time Limit** — Minutes allowed per attempt (e.g., `60`)
   - **Passing Score** — Percentage required to pass (default: `50`)
   - **Evaluation Strategy** — How AI should grade open-ended answers (configured per exam)
4. Click **Next: Add Questions**.

#### Adding Questions

The exam builder supports multiple question types:

1. Click **Add Question**.
2. Enter the **Question Text**.
3. Set the **Marks** (points) for this question.
4. For multiple-choice questions:
   - Click **Add Choice** for each answer option.
   - Check the **Correct** box for the right answer(s).
   - You can mark multiple choices as correct for multi-select questions.
5. Click **Save Question**.
6. Repeat for all questions.
7. Reorder questions by dragging them in the list.

> **Info:** Each question must have at least one correct answer for multiple-choice questions. Open-ended questions do not require choices — the AI will evaluate them.

#### Publishing an Exam

- **Save Draft** — The exam is not visible to students. You can edit it later.
- **Publish** — The exam becomes visible to students on their dashboard. Once published, you can unpublish to hide it.

> **Warning:** Publishing an exam makes it immediately available to all students in your institute. Ensure questions and answers are correct before publishing.

### Managing Students

1. Go to **Admin → Students**.
2. The list shows all students in your institute with their email, status, and role.
3. **Invite a Student:**
   - Click **Invite Student**.
   - Enter the student's email address.
   - The student receives an email with a registration link.
   - The link expires after 24 hours.
4. **Filter Students:**
   - Use the search bar to find by name or email.
   - Filter by role (Student, Admin) or status (Active, Inactive).

> **Tip:** Students who register via the public registration page are automatically assigned to your institute if registration is open.

### Viewing Attempts and Results

1. Go to **Admin → Exams**.
2. Click on an exam to view its details.
3. Click the **Attempts** tab to see all student submissions.
4. Click on an attempt to view:
   - Student's answers
   - AI-generated score and feedback
   - Time taken
   - Section-by-section breakdown
5. **Override a Score:**
   - If you disagree with the AI grading, click **Override Score**.
   - Enter a new score and optional reason.
   - The final score will be your override, not the AI score.
6. **Mark as Reviewed:**
   - Click **Mark Reviewed** to indicate you have checked the AI grading.
   - This helps track which attempts need human attention.

> **Info:** AI grading runs asynchronously via queue workers. Results may take a few minutes to appear after a student submits. If a result is still pending after 10 minutes, check that queue workers are running (see [Installation Guide §7](#step-7-configure-queue-workers)).

### Exporting Results

1. On the **Attempts** tab, click **Export Results**.
2. Choose the format (CSV or Excel).
3. The file downloads with columns: Student Name, Email, Score, Percentage, Status, Time Taken.

### Buying Credits

Credits are required for AI grading. Each exam attempt consumes credits based on the number of questions and the complexity of the evaluation.

1. Go to **Admin → Billing**.
2. Your current credit balance is displayed at the top.
3. Select a credit package created by the Super Admin (e.g., "Starter Pack — 100 credits for $10").
4. Click **Buy Now**.
5. You are redirected to Stripe Checkout to complete payment.
6. After successful payment, credits are added to your balance automatically.

> **Warning:** If your credit balance reaches zero, students can still submit exams, but AI grading will be queued until credits are replenished.

### Viewing Transaction History

On the **Billing** page, scroll down to see your transaction history:

- **Type** — Credit purchase or manual adjustment
- **Credits** — Amount added or removed
- **Amount** — Monetary value (for purchases)
- **Status** — Completed, Pending, or Failed
- **Date** — When the transaction occurred

## Student Guide

### Overview

Students take exams assigned by their Institute Admin and view AI-generated feedback on their performance.

### Dashboard

After logging in, the Student sees:

- **Available Exams** — Published exams ready to take
- **Upcoming Deadlines** — Exams with time restrictions
- **Recent Results** — Scores and feedback from completed exams

### Taking an Exam

1. On the **Dashboard**, find the exam you want to take under **Available Exams**.
2. Click **Start Exam**.
3. You will see the exam instructions and the timer. Click **Begin** to start.
4. Answer each question:
   - **Multiple Choice:** Click the correct answer(s).
   - **Open-Ended:** Type your answer in the text box.
5. Navigate between questions using the sidebar or **Next** / **Previous** buttons.
6. Your answers are **auto-saved** as you go. If you lose connection, your progress is preserved.
7. When finished, click **Submit Exam**.
8. Confirm submission. **You cannot edit answers after submitting.**

> **Warning:** Once you submit, you cannot re-take the exam unless the Admin allows a new attempt. Make sure you have answered all questions before submitting.

> **Tip:** Keep an eye on the timer. If time runs out, your current answers are automatically submitted.

### Viewing Results

Results are only visible after the Institute Admin announces them.

1. Go to **Student → Results**.
2. Find the exam and click **View Results**.
3. You will see:
   - **Overall Score** — Percentage and pass/fail status
   - **Per-Question Breakdown** — Your answer, correct answer, and marks earned
   - **AI Feedback** — For open-ended questions, the AI provides personalized feedback explaining what was correct and what could be improved

> **Info:** AI feedback focuses on conceptual understanding rather than exact wording. Even if your wording differs from the model answer, you may receive full marks if the concepts are correct.

## API Reference Appendix

### Webhook Endpoints

#### Stripe Webhook

**Endpoint:** `POST /stripe/webhook`

**Description:** Receives events from Stripe when a credit purchase is completed.

**Security:**
- Stripe signature verification using `STRIPE_WEBHOOK_SECRET`
- Returns `400 Invalid signature` if verification fails
- Returns `400 Invalid payload` if the payload is malformed

**Events Handled:**

| Event | Description |
|-------|-------------|
| `checkout.session.completed` | A credit purchase was successful. Credits are atomically added to the institute's balance. |

**Metadata Expected:**

| Field | Type | Description |
|-------|------|-------------|
| `institute_id` | integer | The institute to credit |
| `credits` | integer | Number of credits to add |

**Idempotency:**
The endpoint checks `Transaction::where('stripe_session_id', $session->id)` before processing. Duplicate webhooks return `200 Already processed` without double-crediting.

**Response Codes:**

| Code | Meaning |
|------|---------|
| `200 OK` | Event processed or already processed |
| `400 Invalid signature` | Webhook signature verification failed |
| `400 Invalid payload` | Payload could not be parsed |
| `200 Missing metadata` | Required metadata fields were absent (logged as error) |

### LLM Provider Configuration Schema

**Model:** `LlmSetting`

**Fields:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `provider` | enum | Yes | `openai`, `anthropic`, `google`, `openai-compatible` |
| `model` | string | Yes | Exact model identifier from the provider |
| `api_key` | string | Yes | API key from the provider's developer console |
| `base_url` | string | No | **Required only for `openai-compatible`**. API endpoint URL. |
| `is_active` | boolean | Yes | Only one setting can be active at a time |

**Provider-Specific Notes:**

- **OpenAI:** Use models like `gpt-4o`, `gpt-4-turbo`. No `base_url` needed.
- **Anthropic:** Use models like `claude-3-5-sonnet-20241022`. No `base_url` needed.
- **Google:** Use models like `gemini-1.5-pro`. No `base_url` needed.
- **OpenAI-compatible:** Requires `base_url` (e.g., `https://api.deepseek.com`). Supports DeepSeek, Qwen, Together, OpenRouter, Groq, Ollama, and any OpenAI-compatible API.

**Test Connection Endpoint:**

`POST /super-admin/llm/test`

Rate limited to 5 requests per minute. Sends a minimal structured prompt to verify the provider responds correctly.
