# Feature Research

**Domain:** AI-powered exam platform (SaaS)
**Researched:** 2026-04-12
**Confidence:** HIGH

## Feature Landscape

### Table Stakes (Users Expect These)

Features users assume exist. Missing these = product feels incomplete.

| Feature | Why Expected | Complexity | Notes |
|---------|--------------|------------|-------|
| Multi-tenant architecture | Standard for any B2B SaaS platform | HIGH | Must support multiple institutes from day one |
| Role-based access control | Essential for security and workflow separation | MEDIUM | Admin (Institute) and Student roles required |
| Exam creation | Core functionality of any assessment tool | MEDIUM | Support for Multiple Choice, True/False, and Written answers |
| Student exam experience | Prevents data loss and ensures fairness | HIGH | Auto-save, countdown timers, resume capability, question randomization |
| Basic anti-cheat | Maintains basic exam integrity | LOW | Logging when students leave the tab/window |
| Performance analytics | Users need to see results and track progress | MEDIUM | Basic scoring and dashboards for students and admins |

### Differentiators (Competitive Advantage)

Features that set the product apart. Not required, but valuable.

| Feature | Value Proposition | Complexity | Notes |
|---------|-------------------|------------|-------|
| Async AI evaluation | Automates grading of written answers based on concepts, not just keywords | HIGH | Must return score, confidence level, and explanation |
| Dynamic AI model configuration | Allows buyers to control costs and choose their preferred LLM | MEDIUM | Admin panel configuration for API keys (OpenAI, Anthropic, etc.) |
| Teacher override | Builds trust in AI grading by keeping humans in the loop | LOW | Allows teachers to adjust AI-generated grades |
| Pay-per-exam monetization | Aligns platform costs (AI tokens) with revenue for the buyer | HIGH | Institutes buy credits or pay per student/exam |

### Anti-Features (Commonly Requested, Often Problematic)

Features that seem good but create problems.

| Feature | Why Requested | Why Problematic | Alternative |
|---------|---------------|-----------------|-------------|
| Strict lockdown proctoring | Maximum exam security | High technical complexity, friction for users, privacy concerns | Basic tracking (tab/window switching) for v1 |
| Synchronous AI evaluation | Instant feedback for students | High risk of timeouts during exam submission, reliability issues | Asynchronous/batch AI evaluation |
| Native Mobile App | Better mobile experience | High development and maintenance cost | Responsive Web-first SaaS for v1 |

## Feature Dependencies

```
[Multi-tenant architecture]
    └──requires──> [Role-based access control]
    └──requires──> [Pay-per-exam monetization]

[Dynamic AI model configuration]
    └──requires──> [Async AI evaluation]
                       └──requires──> [Teacher override]

[Exam creation]
    └──requires──> [Student exam experience]
```

### Dependency Notes

- **[Pay-per-exam monetization] requires [Multi-tenant architecture]:** Billing must be tracked per institute.
- **[Async AI evaluation] requires [Dynamic AI model configuration]:** The system needs API keys to perform the evaluation.
- **[Teacher override] requires [Async AI evaluation]:** Teachers can only override grades that have been generated by the AI.

## MVP Definition

### Launch With (v1)

Minimum viable product — what's needed to validate the concept.

- [x] Multi-tenant architecture — Required for the SaaS marketplace business model
- [x] Role-based access control — Essential for security
- [x] Exam creation — Core functionality
- [x] Student exam experience — Core functionality
- [x] Basic anti-cheat — Lowers barrier to entry while maintaining basic integrity
- [x] Async AI evaluation — The core value proposition
- [x] Dynamic AI model configuration — Required for buyers to use their own API keys
- [x] Pay-per-exam monetization — Required for the business model

### Add After Validation (v1.x)

Features to add once core is working.

- [ ] Teacher override — Builds trust, but not strictly required for the first successful exam
- [ ] Advanced analytics — Provides deeper insights into student performance

### Future Consideration (v2+)

Features to defer until product-market fit is established.

- [ ] Generative AI Content Creation — Auto-generating questions is a nice-to-have
- [ ] Native Mobile App — Web-first is sufficient for validation
- [ ] Strict lockdown proctoring — Only if basic tracking proves insufficient for the target market

## Competitor Feature Analysis

| Feature | Typical Competitor | Our Approach |
|---------|--------------------|--------------|
| AI Grading | Keyword matching or sync LLM calls | Async LLM evaluation focusing on concepts, logic, and terminology |
| Proctoring | Invasive lockdown browsers | Lightweight tab/window tracking to reduce friction |
| AI Configuration | Locked to a specific vendor | Provider-agnostic, allowing buyers to bring their own API keys |
| Business Model | Monthly subscription | Pay-per-exam / credit-based system |
