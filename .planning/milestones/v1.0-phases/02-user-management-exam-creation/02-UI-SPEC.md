**Components:**
- **Exam Details section:** `<Card>` with form fields
  - `<Input>` — Title (required, max 255)
  - `<textarea>` — Description (optional, max 5000, resizable, min-height 4 rows)
  - `<Input type="number">` — Time Limit (optional, min 0)
  - `<Input type="number">` — Passing Score (min 0, max 100)
- **Questions section:** `<Collapsible>` cards per question
  - Each card header: question type icon + truncated text + point value + reorder arrows + delete button
  - Card body: question-specific form fields
- **Add Question dropdown:** `<Select>` or `<DropdownMenu>` with three options:
  - "Multiple Choice" (lucide: `ListChecks`)
  - "True/False" (lucide: `CircleCheck`)
  - "Written Answer" (lucide: `PenLine`)
- **MCQ options:** `<Input>` per option + `<RadioGroup>` to mark correct answer + "Add Option" button (max 6 options)
- **True/False:** `<RadioGroup>` with two options (True/False)
- **Written Answer:** `<textarea>` for grading guidelines (min-height 6 rows) — this is the D-05 unified rubric field
- **Footer action bar:** sticky bottom or fixed position
  - `<Button variant="outline">` Save Draft
  - `<Button>` Save & Publish

**Form state (Inertia `useForm`):**
```ts
interface OptionData {
  text: string;
  is_correct: boolean;
}

interface QuestionData {
  type: 'multiple_choice' | 'true_false' | 'written_answer';
  text: string;
  points: number;
  options?: OptionData[];       // MCQ only
  correct_answer?: string;       // T/F only: 'true' | 'false'
  grading_guidelines?: string;   // Written only
}

const { data, setData, post, processing, errors } = useForm({
  title: '',
  description: '',
  time_limit_minutes: 60,
  passing_score: 70,
  questions: [] as QuestionData[],
});
```

**Key interactions:**
- **Add question:** appends new item to `data.questions` array via spread operator
- **Remove question:** filters array, triggers re-render
- **Reorder questions:** swap array elements by index
- **Collapsible toggle:** each question card independently expandable/collapsible via `<Collapsible>`
- **Auto-save draft:** optional — debounce `post` to draft endpoint every 30 seconds (Phase 3 consideration)
- **Validation errors:** displayed inline beneath each field; question-level errors show on card header
- **Publish flow:** same form, submit with `status: 'published'` flag vs `status: 'draft'`

## Form Patterns

### Exam Builder — Complex Form State

**State management:** Inertia `useForm` hook with nested object/array structure.

**Array mutation patterns (MUST follow):**
```ts
// ADD: always create new array with spread
function addQuestion(type: QuestionType) {
  setData('questions', [
    ...data.questions,
    { type, text: '', points: 1, /* type-specific defaults */ },
  ]);
}

// UPDATE: map to new array with spread item
function updateQuestion(index: number, field: string, value: unknown) {
  setData(
    'questions',
    data.questions.map((q, i) => (i === index ? { ...q, [field]: value } : q)),
  );
}

// REMOVE: filter to new array
function removeQuestion(index: number) {
  setData('questions', data.questions.filter((_, i) => i !== index));
}

// REORDER: swap elements
function moveQuestion(from: number, to: number) {
  const updated = [...data.questions];
  const [item] = updated.splice(from, 1);
  updated.splice(to, 0, item);
  setData('questions', updated);
}

// NESTED UPDATE (MCQ options):
function updateOption(questionIndex: number, optionIndex: number, field: string, value: unknown) {
  const updated = [...data.questions];
  const question = { ...updated[questionIndex] };
  question.options = question.options?.map((opt, i) =>
    i === optionIndex ? { ...opt, [field]: value } : opt,
  );
  updated[questionIndex] = question;
  setData('questions', updated);
}
```

**Validation error display:**
- Top-level errors (title, description): `<InputError>` beneath the field
- Question-level errors: display on the collapsible card header with a red border
- Option-level errors: display beneath the specific option input
- Error pattern: `errors['title']`, `errors['questions.0.text']`, `errors['questions.0.options.1.text']`

**Submit variants:**
- `post(route('admin.exams.store'), { preserveScroll: true })` — create new
- `put(route('admin.exams.update', exam.id))` — update existing
- Both accept `status` field: `'draft'` or `'published'`

## State Patterns

### Exam Lifecycle State Machine

```
                    ┌───────────┐
   Admin creates    │           │
   ────────────────>│  DRAFT    │
                    │           │
                    └─────┬─────┘
                          │
              Admin clicks│ "Publish"
                          ▼
                    ┌───────────┐
                    │ PUBLISHED │<────── Admin clicks "Unpublish"
                    │           │
                    └─────┬─────┘
                          │
            First student │ starts attempt
            (server-side) │
                          ▼
                    ┌───────────┐
                    │  LOCKED   │  (no reverse transition)
                    │           │
                    └───────────┘
```

**State rules:**
- `DRAFT` -> `PUBLISHED`: admin action, requires at least 1 question
- `PUBLISHED` -> `DRAFT`: admin action (unpublish), allowed even with attempts
- `PUBLISHED` -> `LOCKED`: automatic, triggered server-side when first `ExamAttempt` is created
- `LOCKED` -> any: **no reverse transition**. Exam structure is immutable.

**UI implications:**
- Draft: full edit, delete, publish actions available
- Published: view, unpublish actions available; edit navigates to edit form
- Locked: view-only; edit form rendered with all fields disabled; destructive banner shown

- Header styling: `bg-zinc-50 text-xs font-medium text-zinc-500 uppercase tracking-wider`

### Exam Builder Card Density
- Question card header: `px-4 py-3`, border-bottom when collapsed
- Question card body: `p-4`
- Gap between collapsed cards: `gap-2`
- Gap between expanded cards: `gap-4`

## Keyboard Navigation & Accessibility

- All interactive elements must be reachable via Tab key
- Dialog modals: focus trap, Escape to close, Return to confirm
- Collapsible cards: Enter/Space to toggle
- Form fields: proper `htmlFor`/`id` pairing on all `<Label>` + input pairs
- Radio groups: arrow key navigation between options
- Data tables: `<th scope="col">` on all column headers
- Status badges: `role="status"` or `aria-label` for screen readers
- Destructive actions: `aria-describedby` pointing to confirmation text
