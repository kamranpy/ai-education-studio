# Phase 04.1: exam-creation-enhancements-evaluation-settings - Context

**Gathered:** 2026-04-28

<domain>
## Phase Boundary

Enhancing the Exam Builder UI with tabs, adding class/subject fields, introducing flexible result release strategies (per-exam evaluation strategies and manual result announcement), and improving the student exam experience with separated question types and a dedicated results history.

</domain>

<decisions>
## Implementation Decisions

### Exam Builder Layout
- **D-01:** Exam configuration details (`class_name`, `subject_name`, etc.) will be asked directly while creating the exam on the main builder page.
- **D-02:** The exam creation form will feature three tabs, one for each question type (TF, Written Questions, MCQs).
- **D-03:** The agent has discretion to manage the UI to the best of its ability for these layout changes.

### Evaluation Strategy Scope
- **D-04:** The evaluation strategy ("Show Instantly" vs "Evaluate & Submit") will be configured on a per-exam basis.

### Result Announcement Flow
- **D-05:** Admins first view graded results to optionally override AI scoring or keep it.
- **D-06:** Once the admin sets everything, they are given an option on each exam to "announce the result," which then reveals the result to the students.

### Student Exam Experience
- **D-07:** While taking the exam, students will see questions separated by type (TF / Written / MCQs) rather than mixed together.
- **D-08:** Students can submit each question type separately. Once a specific type is submitted, it is locked and cannot be edited or submitted again.
- **D-09:** A new "Results" option will be added to the student sidebar to allow them to see their historical exam results and data.

### the agent's Discretion
- UI design and layout details for the new three-tab interface and general settings section.

</decisions>
